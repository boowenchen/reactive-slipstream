# Slipstream — demo video script (as recorded, 2:21)

Narration is English text-to-speech with burned-in captions. Every on-chain shot is a live explorer page (Blockscout / Reactscan) for a real testnet transaction listed in README.md; cards and stills are rendered from the repository's own evidence, test output and the live status page. No simulated activity is shown as a transaction.

| Time | Shot | Narration |
|---|---|---|
| 0:00–0:14 | Slipstream · architecture | “Two pools, one token pair, different prices. Slipstream turns pool reserve events into guarded, atomic trades through Reactive Network, and measures how quickly that happens against a polling keeper.” |
| 0:14–0:23 | Base Sepolia · dislocation swap — origin (calibration loop 1) | “A real test-token swap on Base Sepolia pushes one pool's price out of line. The pool emits a reserve update with a sequence number.” |
| 0:23–0:38 | Lasna · Reactive decision and callback request (loop 1) | “The Reactive contract on Lasna caches both pools' reserves, checks the spread, and quotes a round trip. Its decision is keyed by the source transaction and log index, so every opportunity can be traced end to end.” |
| 0:38–0:57 | Base Sepolia · callback executes the two-swap round trip (loop 1) | “On Base, the executor accepts only the callback proxy and this exact Reactive contract. It runs both swaps atomically, with an input cap, a deadline, slippage bounds and a minimum profit. If the quote no longer meets those guards, the whole trade reverts.” |
| 0:57–1:28 | Formal run · 136 + 136 real trials | “For the benchmark, we ran two independent fixtures: one hundred thirty-six formal opportunities handled through Reactive, and one hundred thirty-six handled by a polling keeper that sends real transactions. All of them completed. Measured by Base block timestamps, from the origin transaction to the callback, Reactive took a median of two seconds, versus eight seconds for this keeper. From submitting the swap to seeing the trade complete, it was about seven seconds versus fourteen.” |
| 1:28–1:48 | Transaction ledger · every attempted trial | “We lead with block timestamps because our RPC observer compresses short intervals: in one hundred thirty of the Reactive samples, it saw the callback before the Reactive transaction. The keeper is a simple baseline, not the fastest possible one. Every sample links back to its transactions in the published ledger.” |
| 1:48–2:06 | Live rejection of a stale quote | “The guards are exercised on-chain too. Here a second swap closes the gap one second after it opened. The Reactive decision still fires, but when its callback lands the trade would lose money, so the executor reverts it: nothing is completed and no tokens move.” |
| 2:06–2:20 | Local tests and a deliberate mutation | “The test suite catches deliberately broken safety properties: flip the pool fee in the wrong direction, and the invariant fails. Slipstream measures a mechanism on testnet. It does not claim mainnet profitability.” |
